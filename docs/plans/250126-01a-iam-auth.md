# Plan: AWS IAM Auth on tRPC Lambda Function URL

## Overview

Secure the tRPC Lambda Function URL with AWS IAM authentication to prevent unauthorized access. The Remix server will sign requests using AWS SigV4.

## Files to Modify

| File | Change |
|------|--------|
| `infra/trpc.ts` | Enable IAM auth on Function URL |
| `infra/site.ts` | Add Lambda invoke permissions |
| `packages/web/app/api.server.ts` | Add SigV4 request signing |
| `packages/web/package.json` | Add `aws-sigv4-fetch` dependency |

## Implementation Steps

### 1. Enable IAM Auth on Function URL

**File:** `infra/trpc.ts`

Change `url: true` to use IAM authorization:

```typescript
const trpc = new sst.aws.Function('RasikaTRPC', {
  url: {
    authorization: 'iam',  // Changed from: url: true
  },
  link: [database, searchReindexFunction, searchBucket],
  handler: './packages/trpc/src/index.handler',
  environment: {
    DYNAMODB_TABLE: database.name,
    AWS_REGION: undefined,
    SEARCH_INDEX_BUCKET: searchBucket.name,
  },
});
```

### 2. Add Lambda Invoke Permissions to Site

**File:** `infra/site.ts`

Add explicit permissions for the Remix Lambda to invoke the tRPC Function URL:

```typescript
const site = new sst.aws.React('RasikaWeb', {
  link: [bucket, trpc],
  path: 'packages/web/',
  domain: {
    name: $app.stage === 'prod' ? 'rasika.life' : `${$app.stage}.rasika.life`,
    redirects: $app.stage === 'prod' ? ['www.rasika.life'] : [`www.${$app.stage}.rasika.life`],
    dns: sst.aws.dns({
      zone: 'Z0190677U1NK4BAEXE0M',
    }),
  },
  environment: {
    STAGE: $app.stage,
  },
  permissions: [
    {
      actions: ['lambda:InvokeFunctionUrl', 'lambda:InvokeFunction'],
      resources: [trpc.arn],
    },
  ],
});
```

### 3. Install SigV4 Signing Package

```bash
cd packages/web && pnpm add aws-sigv4-fetch
```

### 4. Add Request Signing to tRPC Client

**File:** `packages/web/app/api.server.ts`

```typescript
import type { AppRouter } from '@rasika/trpc';
import { createTRPCClient, httpBatchLink } from '@trpc/client';
import { createSignedFetcher } from 'aws-sigv4-fetch';
import { Resource } from 'sst';

export type { RouterOutput } from '@rasika/trpc';

// Create a signed fetcher for Lambda Function URLs
const signedFetch = createSignedFetcher({
  service: 'lambda',
  region: 'us-east-1',
});

export const client = createTRPCClient<AppRouter>({
  links: [
    httpBatchLink({
      url: Resource.RasikaTRPC.url,
      fetch: signedFetch,
    }),
  ],
});
```

## How It Works

1. **IAM Auth on URL** - Lambda Function URL requires AWS SigV4 signed requests
2. **SST Linking** - Site is linked to tRPC, gets `Resource.RasikaTRPC.url`
3. **Explicit Permissions** - Site Lambda role gets `lambda:InvokeFunctionUrl` permission
4. **Signed Requests** - `aws-sigv4-fetch` signs all tRPC HTTP requests using the Lambda's execution role credentials

## Notes

- All tRPC calls happen server-side in Remix loaders, so signing works seamlessly
- Credentials are auto-loaded from Lambda execution environment
- No changes needed to tRPC server code itself
